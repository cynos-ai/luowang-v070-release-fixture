## 目的

确认规格行为 3「密码错误和不存在的邮箱使用统一错误信息」，避免账户枚举；并确认失败登录不建立 Session。

## 依据

- 规格 `docs/changes/cynos-website-auth/spec.md` 行为 3 与验收条件「……错误密码有明确失败响应」。
- 实现 `src/server/security/auth.ts`（`login` 对不存在邮箱与错误密码统一返回失败）。
- 初始化侦察（execution.md）：浏览器 UI 对错误密码与已删除账号均显示统一凭据错误。

## 前置条件

- 隔离的非生产测试环境（可删除测试账号）；
- 一个已注册的测试邮箱。

## 步骤

1. 注册测试邮箱 A 并保留其正确凭据，随后退出到未登录状态。
2. 用邮箱 A + 错误密码在登录表单提交。
3. 用不存在的邮箱 + 任意密码提交登录（若 UI 原生校验拦截，则用受控 HTTP 客户端对该同源路径提交）。
4. 对比两次失败的提示或错误信息，并读取 `GET /api/auth/status`。

## 期望

- 错误密码与不存在邮箱登录均被明确拒绝（4xx），错误信息一致，不区分邮箱是否存在；
- 失败后 `GET /api/auth/status` 为未登录，未建立 Session。

## 需要记录

- 两种失败的实际状态码与错误信息（用于比较是否一致）；
- 失败后的会话状态；
- 测试账号删除与清理核验。
