## 目的

确认用户登录后重新加载页面不会丢失会话，并且退出登录会撤销会话。

## 前置条件

- 本 Run 注册一个独立合成测试账号（邮箱或昵称以 `luowang-<RunID>-` 开头以便登记与清理），不使用、不删除环境中已有的预置账号；
- 浏览器允许第一方 Cookie。

## 步骤

1. 使用合成测试账号登录。
2. 刷新浏览器页面。
3. 确认页面仍显示当前用户。
4. 退出前先用同一实际登录的客户端固化当前会话；携带该固化会话请求 `GET /api/me`，确认返回 200，作为「原会话原本有效」的正对照。
5. 点击退出登录。
6. 用步骤 4 的同一固化会话再次请求 `GET /api/me`，确认返回 401，以证明是服务端撤销了该会话，而非客户端只是丢弃了 Cookie。
7. 重新登录后，同样先固化新会话并确认 `GET /api/me` 返回 200 正对照，再删除当前合成测试账号。
8. 用步骤 7 的同一固化会话请求 `GET /api/me` 确认被拒，再用原凭据尝试登录。

## 期望

- 刷新后显示同一用户；
- 退出后页面回到登录状态；
- 退出后的 Session 访问受保护接口返回 401；
- 删除测试账号后旧 Session 和原凭据均不可用。

## 需要记录

- 登录和刷新后的用户资料；
- 退出前后的 HTTP 状态；
- Cookie 是否为 HttpOnly 和 SameSite=Strict；
- 固化会话在破坏操作前后的两段结果（操作前 200 正对照、操作后 401），以及证明请求确实携带了所保存 Cookie 的绑定证据（Cookie 原文不落盘）；
- 删除后的提示、旧 Session 固化重放结果和原凭据登录结果；
- 合成账号的登记标识与清理核验。
